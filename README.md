# X-Plane 12 局域网便携 EFB

一个只在本地局域网工作的 iPad 移动地图 EFB。Windows 单文件桥接器同时接收 X-Plane 12 UDP、托管网页并通过 WebSocket 推送遥测；不需要公网、云服务器、DDNS、NAT 配置或端口转发。

> 仅用于飞行模拟，不得用于真实导航。

## 架构

```text
X-Plane 12（电脑）
   │ DATA/UDP：位置、速度、姿态等
   ▼
XPlaneEfbBridge.exe
   ├─ UDP 监听：0.0.0.0:49000（可配置）
   ├─ DATA 包解析与字段合并
   ├─ HTTP 静态网页：0.0.0.0:8080
   └─ WebSocket：ws://电脑IP:8080/ws
                 │
                 ▼
        同一 Wi-Fi 的 iPad Safari/PWA
```

网页和 WebSocket 由同一个 exe、同一个地址提供，因此不需要 CORS。浏览器不能直接监听 UDP，exe 是数据链路中必需的桥接组件。

## 功能

- 单文件 Windows x64 exe；目标电脑无需安装 Node.js 或 .NET。
- **可视化设置界面**：托盘“设置…”里直接查看/修改/保存配置，不需要再用记事本编辑 JSON；端口类改动会明确提示需要重启，其余设置立即生效。
- 原生托盘菜单、后台运行、开机自启、重新加载、显示 iPad 地址，以及可选的 SimBrief 代理设置。
- 默认 UDP 49000，支持一个或多个候选监听端口和可选 X-Plane 来源 IP 白名单。
- 自动识别合法 `DATA` 包和发送端 IP；托盘显示实际 XP12 来源、端口和在线 iPad 数。
- 解析 Data Output 行 3、4、17、20：IAS/TAS/地速、Mach/VVI/G、俯仰/滚转、真/磁航向、经纬度及 MSL/AGL 高度。
- 分包状态合并；缺少某一数据行不会影响其他字段；未知协议/行安全忽略。
- iPad Safari 响应式 UI、横竖屏、安全区和触摸操作；仪表、状态、地图按钮和抽屉采用适合平板阅读的放大字号与触摸尺寸。
- Leaflet 本地打包（不依赖第三方旋转插件）；北向上/航向向上一键切换、飞机图标、2,000 点轨迹、跟随、平移、缩放和清轨迹。
- 航向向上用容器级 CSS 旋转实现：底图、航迹和航路一起平滑转动，飞机图标始终朝上；指针坐标会换算回地图坐标系，因此双指缩放、点按仍然准确。
- OpenStreetMap 是唯一主力底图，另可选配一个获得授权的 XYZ 底图。
- 航迹使用「外发光 + 深色描边 + 亮色主线」三层描边并标出起点，在明亮底图上依然清晰，不遮挡飞机图标。
- 可选 SimBrief 航路叠加：拉取你自己的飞行计划，绘制航路虚线、航点（含航路与高度提示）以及起飞/降落/备降机场。
- 航点名称直接标在地图上，缩放小于 9 级时自动隐藏，并按屏幕间距过滤重叠，长航线不会糊成一片。
- 本地归档每次拉到的计划（最多 12 份），可在 iPad 上切换历史计划；并可在 EFB 内直接浏览完整 OFP。
- 可选 OpenWeatherMap 天气图层（云/降水/风/温度/气压）：Key 只存在电脑上，iPad 通过桥接器取瓦片，自动署名。
- WebSocket 自动重连、UDP 3 秒超时状态和诊断抽屉。
- PWA manifest；HTTPS 安全上下文下支持 service worker 应用壳缓存。

## 最终用户使用 exe

已构建的文件：

```text
windows-bridge\dist\XPlaneEfbBridge.exe
```

1. 将这个 exe 复制到固定目录，例如 `C:\Program Files\XPlaneEfbBridge` 或用户文档目录。
2. 双击运行。程序不会显示主窗口，会出现在 Windows 系统托盘。
3. 首次运行会创建 `%LOCALAPPDATA%\XPlaneEfbBridge\bridge-config.json` 并显示 iPad 访问地址。
4. Windows 防火墙弹窗出现时，只允许“专用网络”。
5. 右击托盘图标 → **设置…**，在图形界面里改配置、点“保存”。
6. 托盘菜单还提供：在本机打开 EFB、显示访问地址、重新加载配置（重启服务）、开机自动启动、高级（用记事本打开配置文件 / 打开配置文件夹）、退出。

> 只有双击同一个 exe 的第二个实例会被拦下并提示“已经在运行”，请到托盘里打开设置——这样可以避免两个进程抢同一个端口、同时写同一个配置。

默认配置：

```json
{
  "UdpPorts": [49000],
  "WebPort": 8080,
  "SourceIp": "",
  "CustomBaseMapName": "",
  "CustomBaseMapUrl": "",
  "CustomBaseMapAttribution": "",
  "SimbriefUser": "",
  "SimbriefApiUrl": "",
  "WeatherApiKey": "",
  "ProxyMode": "system",
  "ProxyUrl": ""
}
```

**推荐用托盘“设置…”修改配置**，保存后端口类改动会询问“是否现在重启服务”，其它设置立即生效。手动改 JSON 也可以，改完请从托盘选择“重新加载配置（重启服务）”。`SourceIp` 留空时接受局域网内任意发送端；如果网络中有多台模拟器，建议填写 X-Plane 电脑的固定局域网 IPv4。

旧版配置中的 `AuthorizedChartTileUrl`、`AuthorizedChartAttribution`、`NavigraphExternalUrl` 已不再使用。程序**不会自动删除**它们：设置窗口会提示这些字段已废弃，只有你勾选“保存时删除已废弃的旧字段”并保存时，才会先备份再清理；你自己添加的其他键始终保留。

如果已有获得授权、与 Leaflet 兼容的 XYZ 服务，可配置：

```json
"CustomBaseMapName": "我的底图",
"CustomBaseMapUrl": "https://tiles.example.com/{z}/{x}/{y}.png",
"CustomBaseMapAttribution": "© 服务提供商"
```

不要直接套用未获许可的地图瓦片地址；需要遵守服务商的使用和署名条款。

### 配置文件自动修复

配置文件必须只有一个根 JSON 对象。新版若发现文件中误拼接了两个对象，或一个合法对象后带有 `(` 等多余内容，会选择包含 `WebPort` 和 `UdpPorts` 的当前局域网配置，先将原文件备份为 `bridge-config.json.invalid-时间戳.bak`，再重写为合法 JSON。旧版的 `CloudUrl`、`SessionId`、`IngestToken` 和已经回退的天地图字段不会写入新配置。

## 设置界面

### 地图侧边栏、航班状态浮层、天气图标

- **侧边栏**：顶栏 ☰ 展开/收起。宽屏（≥700px）时侧边栏**推挤地图**（地图宽度 = 视口 − 侧边栏），地图不被遮挡，拖拽/缩放/点选/航向向上旋转全部照常可用；按住侧边栏左边缘可以拖动改宽（300–560px），开合与宽度都会记住。窄屏（<700px，例如 iPad 竖屏）自动降级为覆盖式抽屉 + 遮罩，避免把地图挤得过窄。**夜间模式**开关也在侧栏“底图”里（见下）。
- **航班状态浮层**（默认显示在**顶栏下方、水平居中**，可拖动、可折叠、可隐藏，位置与状态会记住）：
  航班号 / 机型与注册号 / 起降机场与**计划离港、到达时间（UTC）** / 航路时间 / 进度条与百分比 / 剩余距离 / 剩余时间 / 预计到达（与计划时间对比早或晚）/ 地速 / 高度 / 航向 / 状态（地面·爬升·巡航·下降）/ 最近更新时间。
  剩余距离按“飞机在航路上的投影点到终点”计算，没有航路时退回大圆距离（标注“直飞”）；**地速无效或小于 30 kt 时剩余时间与预计到达显示“未知”**，不会给出错误时间。
  隐藏方式：卡片右上角 ✕，或右侧 ✈“状态”按钮；隐藏后**左侧竖列（天气图标正上方）会出现一个 ✈ 小图标**，点它即可重新展开。拖动卡片时会被限制在“顶栏以下、按钮列以外”的区域，因此不会再被顶栏或按钮挡住；卡片只占自身范围，不拦截地图的拖拽/缩放/点选。
- **天气图标**：地图左下角，云形大图标点开后在其上方展开 5 个子图标（云/降水/风/温度/气压），点一下开启、再点一下关闭；开启时子图标与主图标都有高亮，未配置 Key 时子图标禁用并给出提示。图标为内联 SVG，不依赖图标库。
- **航司徽章**：航班卡片左上角按呼号的 ICAO 三字码显示徽章（如 CA→CCA/中国国际航空、CX→CPA/国泰航空），颜色由三字码决定；名字与 IATA 码来自内置表 `public/data/airlines.json`（离线、90 家主要航司）。**不内置任何第三方航司 logo**（logo 属商标素材，公开渠道多为非自由许可），如果你有自己的授权来源，可在设置里填写 logo 地址模板（`{icao}`/`{iata}` 占位符），加载失败会自动回退到三字码徽章。
- **夜间模式**：侧栏“底图”里的开关，深色底图用 CSS 滤镜实现（只作用于 OSM 底图图层）：航迹、SimBrief 航路、天气叠加、飞机图标、卡片与所有控件的颜色都不受影响，开关状态会被记住。OSM 官方没有暗色瓦片；若将来想要更专业的暗色底图（CARTO 等，需要 API key），可把 key 走桥接器代理后接入。

右击托盘图标 → **设置…**，四个分组：

| 分组 | 内容 | 生效方式 |
| --- | --- | --- |
| 连接 | 网页端口、X-Plane UDP 端口、只接受某个来源 IP | **需要重启服务**（保存后会询问是否立即重启） |
| 地图 | OpenStreetMap / 自定义 XYZ 底图（名称、URL 模板、署名） | 保存后立即生效，iPad 刷新/重开网页即可看到 |
| SimBrief | Pilot ID 或用户名（默认遮罩，可点“显示”）、代理、测试按钮 | 保存后立即生效 |
| 天气 | OpenWeatherMap API Key（默认遮罩、可测试）+ **天气专用代理**（系统代理/直连/自定义，可带认证，密码加密保存） | 保存后立即生效，iPad 刷新网页即可看到图层 |
| 高级 | 开机自动启动、已废弃字段清理、打开配置文件/文件夹、当前状态诊断 | 开机自启立即生效；清理随保存执行 |

界面上的几个约定：

- **保存 / 取消 / 恢复默认值**：只有点“保存”才会写入文件；“恢复默认值”只改界面上的值，仍需保存。
- **校验**：端口范围与重复、端口是否被占用、IPv4 格式、XYZ 模板占位符、SimBrief 用户格式、代理地址格式；有错会在对应字段下用红字提示，并且**不会写出任何文件**。
- **迁移安全**：打开设置时显示的就是当前真正生效的值。保存前先在同一个目录生成带时间戳的备份（`bridge-config.json.20260911-053012.bak`），写入采用“临时文件 + 原子替换 + 回读校验”。如果在设置窗口打开期间配置文件被其它程序改过，会先问你是覆盖（仍然先备份）还是重新载入。
- **不产生垃圾文件**：如果保存的内容与文件里已有的完全一致，程序不会重写文件、也不会新增备份，只提示“没有重复写入”。
- **敏感项**：SimBrief Pilot ID 默认遮罩、只保存在本机、不会下发给 iPad、不写日志；代理地址不接受“用户名:密码”写法，需要认证请用“系统代理”（凭据由 Windows 保管）。

### 代理（可选）

`ProxyMode` 默认为 `system`（使用 Windows 系统代理，含 PAC 自动配置；没有配置系统代理时等价于直连），也可以选 `none`（始终直连）或 `manual`（例如 `http://127.0.0.1:7890`）。

它**只影响桥接器自己发起的出网请求**，目前就是 SimBrief 航路拉取：局域网里的 UDP 遥测、WebSocket、网页服务完全不走代理；iPad 上的 OpenStreetMap 瓦片是 iPad 自己下载的，也不受这个开关影响（那部分由 iPad 上的代理/规则决定）。Node 调试模式没有实现代理设置，只有 exe 支持。

### 天气图层（OpenWeatherMap，可选）

在 `%LOCALAPPDATA%\XPlaneEfbBridge\bridge-config.json` 里填 `WeatherApiKey`（或在托盘“设置…”→ 天气 页填写，带“测试连接”按钮），iPad 地图**左侧的天气图标**里就会出现 **云 / 降水 / 风 / 温度 / 气压** 五个图层，选择结果保存在 iPad 本地。留空即关闭该功能。

**天气请求的代理**（在同一页里设置，默认“使用系统代理”）：

- 三种模式：`使用系统代理`（默认，含 PAC）、`不使用代理`（直连）、`自定义代理`（填 `http://主机:端口`）。
- 自定义代理**支持认证**：填“代理用户名 + 代理密码”。密码用 Windows DPAPI 按当前用户加密后写入配置，文件里不是明文、也不进日志；换电脑或换 Windows 账号后需要重新输入（界面会提示）。
- 与“高级”页里的全局代理（SimBrief 用）**互不影响**：`WeatherProxyMode` / `WeatherProxyUrl` / `WeatherProxyUser` / `WeatherProxyPassword` 只作用于 `tile.openweathermap.org`。
- “测试连接”会用**天气代理**去取一张 zoom 0 的瓦片，并区分“Key 被拒绝”和“代理/网络不通”；出错信息里的凭据一律被抹成 `***`。

> 修复记录：早期版本里“设置窗口的连接测试”会把共享的 HttpClient 释放掉，导致**第二次**测试和地图上的天气请求都报 `Cannot access a disposed object`。现在改为按代理配置缓存客户端、调用方不释放、被释放时自动重建并重试一次，自检里也加了“连续多次请求”的回归用例。

### 机场地面数据（滑行道/标线/机位）——研究结论

详见 [`docs/GROUND-DATA.md`](docs/GROUND-DATA.md)。结论与实现：**读本机 X-Plane 的 `apt.dat`**（滑行道/机坪铺面、地面标线、滑行道标牌编号、机位/启动位、ATC 滑行路线，与模拟器所见一致；只读本机文件、不打包）；其余来源（OurAirports 无滑行数据、OpenAIP 无地面数据、FAA 仅美国且非矢量、MSFS BGL 需逆向）都不适合。

用法：

1. 电脑端托盘 → 设置… → **地图** 页：填 **X-Plane 12 安装目录**（含 `Resources`、`Custom Scenery` 的那一层，可直接粘贴路径，也可点“选择文件夹…”用内置选择器挑选），并设置 **地面图层最小缩放**（默认 15）。选好后输入框下方会立刻显示“找到几个 apt.dat、共多少 MB”，保存后**无需重启服务**：索引会在后台开始建立。
2. iPad 上点地图左侧 **🛬 地面** 图标开启。未配置目录时点击会提示去哪配置；配置好之后点击同一图标会重新读取配置，不必先刷新网页。
3. 缩放到设定级别及以上时才请求并绘制：跑道（含中线）、滑行道/机坪铺面、地面标线、ATC 滑行路线；再放大一级显示**机位号（如 A8）与滑行道标牌文字**。低于阈值时完全不渲染（不发请求、不占资源），关闭开关立即清空。

实现要点：桥接器先建立“ICAO → 文件行号”的索引（带磁盘缓存，apt.dat 变化后自动重建），只有真正放大到某个机场附近时才解析**那一个机场**的记录区间，结果缓存；前端用独立 canvas pane（位于底图之上、航迹/航路之下）绘制矢量，标签上限 60 个。

- **首次索引在后台进行**：默认机场包的 apt.dat 可能有几十到上百 MB，索引是一次性的（结果存 `apt-index.json`，文件变了才重建）。建立期间 iPad 会提示“正在建立机场索引…”，不会白屏也不会阻塞别的功能。
- **路径容错**：选到上一级（例如包含 `X-Plane 12` 的目录）、`X-Plane 12` 本身、`Resources` 目录，甚至直接选 `apt.dat` 文件都可以，程序会自动纠正到安装根目录后再读取。
- `Custom Scenery` 里的机场包会覆盖默认机场：`<包>\Earth nav data\apt.dat` 与 `<包>\apt.dat` 都会被索引，后索引的覆盖先索引的。
- **画出来长什么样**（刻意与 OpenStreetMap 自带的机场渲染区分开，因为底图本身也会画淡灰色滑行道和自己的一套文字）：
  - 机坪/滑行道**铺面**：蓝灰色填充 + 亮蓝色描边；
  - **地面标线**（滑行道中线等）：亮黄色，随缩放略加粗；
  - **跑道**：深色外框 + 灰面 + 白色虚线中线；
  - **机位/停机位**：黄点 + 黄色标签（如 `A8`），滑行道标牌用青色标签（如 `B`、`A 16L-34R`），放大到阈值以上一级才出现；
  - ATC 滑行路线（非实际标线）：淡蓝色虚线，颜色刻意压得很轻。
- **怎么确认它真的加载了**：数据到达时会弹一次提示「KSEA 地面数据已加载：跑道 2 · 铺面 18 · …」，同时抽屉里「地面图层」一行会一直显示当前机场与要素数量；如果只是缩放到阈值以下，点开开关时会提示「要缩放到 15 级以上才会显示（当前 N）」。
- **改了 apt.dat 不会热重载**：已解析的机场会缓存在内存里。装了新机场包/改了地景后，重新保存一次设置（会强制重建索引）或重启 exe 即可。

- **Key 不会下发到 iPad**：iPad 只向桥接器请求 `/api/weather/tile/{图层}/{z}/{x}/{y}.png`，由电脑带 Key 去取瓦片，并在内存里缓存 10 分钟；因此前端 URL、网页源码、iPad 的网络请求里都不会出现 Key（前端只从 `/api/config` 知道“是否已配置”）。
- **额度保护**：桥接器把上游请求限制在每分钟 50 次（免费额度是 60 次/分钟、100 万次/月），并在 zoom 12 以上复用 zoom 12 的瓦片（`maxNativeZoom`），避免缩放到街道级别时刷爆额度。超限时该瓦片返回 429，界面不受影响。
- **署名**：只要启用了天气图层，地图右下角会自动显示 “天气：© OpenWeather” 链接（这是 OpenWeatherMap 的使用条款要求）。数据只用于你自己的客户端显示，不做再分发。
- **代理**：天气瓦片与 SimBrief 请求共用同一条出网通道，也就是沿用“高级”里的代理设置（默认系统代理）。
- 排查用：如果 Key 测试失败提示 401，通常是新申请的 Key 还没生效（一般十几分钟）或复制时带了空格。

### 历史计划与完整 OFP

- **SimBrief 抓取接口只返回“最新一份”计划。** 实测（2026-09-11）：给 `xml.fetcher.php` 追加 `request_id` 或 `sequence_id` 参数会被忽略（返回的还是最新计划，长度一致）；唯一被识别的选择参数是 `static_id`，而它只对“通过 API 生成过的计划”有效——网站生成的计划该字段为空，所以拿不到历史计划。
- 因此桥接器把**每次成功拉到的计划都归档在本机**：`%LOCALAPPDATA%\XPlaneEfbBridge\flightplan-history.json`，最多 12 份，只列出当前 SimBrief 账号的计划（账号哈希隔离）。iPad 抽屉里的“**历史计划（本地归档）**”下拉列表可以随时切回任意一份，**切换不会再联网**；重复拉到同一份（相同 `request_id`）只更新、不重复堆积。
- 前提是那份计划**曾经被本程序拉取过**——首次拉取之前就存在、之后又被覆盖掉的历史计划，SimBrief 不对外提供，任何工具都取不到。
- 归档里同时保存**完整 OFP 文本**：SimBrief 的 `text.plan_html`（一整段 `<pre>`）会转成纯文本（去掉标签与注释、保留排版），并附上 `tlr_section` 起降性能报告。点抽屉里的“**查看完整 OFP**”即可在 iPad 上滚动浏览——纯文本渲染，不会把远程 HTML 注入页面。

### 关于默认 49000

按需求默认监听 UDP 49000。但 49000 也经常被 X-Plane 用作自身接收端口：如果 exe 和 X-Plane 在同一台电脑上出现“UDP 49000 不可用”或端口占用，请将配置改为：

```json
"UdpPorts": [49003]
```

同时把 X-Plane 的数据发送目标端口改成 49003。端口号本身没有特殊要求，两端一致即可。也可配置候选端口，例如 `[49003, 49002]`；程序会同时监听并自动显示首先收到合法 DATA 包的端口。UDP 没有服务发现握手，因此无法自动询问 X-Plane 当前输出端口。

## X-Plane 12 设置

1. 打开 **Settings → Data Output**。
2. 在下列行勾选最右侧 **Network via UDP**：
   - `Speeds`，常见索引 3；
   - `Mach, VVI, g-load`，常见索引 4；
   - `Pitch, roll, & headings`，常见索引 17；
   - `Latitude, longitude, & altitude`，常见索引 20。
3. 设置 UDP 接收目标：
   - X-Plane 与 exe 同机：目标 IP 使用 `127.0.0.1`；
   - X-Plane 与 exe 不同电脑：目标 IP 使用运行 exe 的电脑局域网 IPv4；
   - 目标端口使用桥接器 `UdpPorts` 中的一个，默认 49000。
4. 建议输出频率 5–10 Hz；更高频率通常不会改善移动地图体验。

字段和行名称以 X-Plane 当前设置界面为准。可参考 Laminar 的[官方 Data Set Output Table](https://www.x-plane.com/kb/data-set-output-table/)。

## iPad 访问

电脑和 iPad 必须：

- 连接同一个局域网/Wi-Fi；
- 不使用阻止设备互访的访客网络；
- Wi-Fi 路由器未启用 AP isolation/client isolation；
- 电脑网络类型设为 Windows“专用网络”。

托盘菜单会显示检测到的访问地址。也可在 PowerShell 查询 IPv4：

```powershell
Get-NetIPAddress -AddressFamily IPv4 |
  Where-Object {$_.IPAddress -notlike '169.254*' -and $_.InterfaceAlias -notlike '*Loopback*'}
```

iPad Safari 打开，例如：

```text
http://192.168.1.25:8080
```

不要在 iPad 上使用 `localhost` 或 `127.0.0.1`，它们指向 iPad 自己。

## Windows 防火墙

首选首次运行时允许 exe 的“专用网络”访问。若需要显式端口规则，以管理员身份运行 PowerShell：

```powershell
New-NetFirewallRule -DisplayName "X-Plane EFB Web" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow -Profile Private
New-NetFirewallRule -DisplayName "X-Plane EFB UDP" -Direction Inbound -Protocol UDP -LocalPort 49000 -Action Allow -Profile Private
```

如果改用 49003，应同步修改第二条规则。不要为“公用网络”开放，也不要在路由器上配置端口转发。

## HTTP、WebSocket 和 PWA 限制

- 网页通过 `http://电脑IP:8080` 加载，并自动连接同源 `ws://电脑IP:8080/ws`；不存在 HTTPS 页面连接明文 WS 的 mixed-content 问题。
- 由于网页、API、WS 同源，不需要 CORS；不要把前端单独放到 GitHub Pages。
- 局域网 IP 上的普通 HTTP 通常不属于 Safari 安全上下文，service worker 不会注册，离线应用壳不可靠。
- Safari 仍可通过分享菜单尝试“添加到主屏幕”，但不同 iPadOS 版本对普通 HTTP 的安装/全屏行为可能不同。
- 如果以后希望获得完整 PWA 安装和 service worker，可在局域网内用受 iPad 信任的证书和反向代理提供 HTTPS；这不是当前运行的必要条件。
- OSM 和自定义在线瓦片仍需要互联网。飞机数据链路完全在局域网内，但没有互联网时底图可能为空。

### Shadowrocket 与 OSM

- Shadowrocket 开启后不一定影响局域网访问，关键取决于路由规则。应让 `192.168.0.0/16`、`10.0.0.0/8` 和 `172.16.0.0/12` 走 `DIRECT`，不要启用会把本地网络也强制送入隧道的选项。电脑热点地址 `192.168.43.5` 属于应直连的私网地址。
- EFB HTML、WebSocket 和飞机遥测来自电脑局域网地址；OSM 瓦片则由 iPad Safari 直接请求 `https://tile.openstreetmap.org`。因此电脑能访问 OSM 并不会自动替 iPad 加载瓦片。
- 推荐在 Shadowrocket 规则模式中让电脑局域网地址走 `DIRECT`，让 `tile.openstreetmap.org` 走 `PROXY`。这样 EFB 数据仍在局域网内，地图瓦片经 iPad 的代理节点访问。
- 也可在 `CustomBaseMapUrl` 中配置合法授权且 iPad 可访问的 XYZ 服务。不要随意搭建公共 OSM 代理；如确需由电脑代理瓦片，必须遵守 OSM 的缓存、标识、署名和使用量政策。

## SimBrief 航路叠加

可选功能：把你自己 SimBrief 账号里最新生成的飞行计划画到地图上。完整调研（端点、认证、限制、字段、合规结论）见 [`docs/SIMBRIEF.md`](docs/SIMBRIEF.md)，要点如下：

- 读取“某位飞行员的最新 OFP”不需要 API Key，只需要 Pilot ID 或 Navigraph 用户名：`https://www.simbrief.com/api/xml.fetcher.php?userid={PilotID}&json=v2`。
- 官方明确要求该端点**只能由用户操作触发，不能轮询**，否则可能被防火墙封禁。因此本项目：
  - 只在抽屉里点击“获取/刷新航路”时才向 SimBrief 请求；
  - 结果缓存在运行 exe 的电脑上（`%LOCALAPPDATA%\XPlaneEfbBridge\flightplan-cache.json`），重启后无需再次请求就能显示；
  - 两次请求之间强制至少间隔 30 秒，避免误触造成连续调用。
- 请求由电脑上的桥接器发出，Pilot ID 只保存在本地配置文件里，不会下发到网页，iPad 也不需要能访问 SimBrief。
- 显示内容：航路虚线、航点（点按查看航路与高度）、起飞/降落/备降机场标签；航点坐标来自计划本身，叠在 OSM 底图与飞机当前位置之上。

配置示例（Pilot ID 是 1–7 位数字；也可填写 Navigraph 用户名）：

```json
{
  "SimbriefUser": "123456",
  "SimbriefApiUrl": "",
  "ProxyMode": "none"
}
```

`SimbriefApiUrl` 留空即使用官方端点，仅在你有自己的代理时才需要填写（例如网络受限环境）。SimBrief 是 Navigraph 旗下的飞行模拟服务，数据仅供模拟飞行使用，不得用于真实导航。

这些字段都可以在托盘“设置…”→ SimBrief 页里填写：填好 Pilot ID 后点“测试并获取航路”，成功会显示起降机场与航点数，再点“保存”。如果电脑需要经代理才能访问 `www.simbrief.com`，把“代理”改成“使用系统代理”或填手动代理地址（只影响这一路的出网请求）。

**想看到航点而不是一条直线**：需要 SimBrief 计划里带航点明细，也就是生成计划时启用 **Detailed Navlog（详细航路日志）**；关闭时接口里 `navlog` 是空字符串，本项目只能画出起降机场之间的直连线（设置窗口会提示你这一点）。在 SimBrief 的 New Flight → Optional Entries 里把 `Detailed Navlog` 设为 `1`（默认开启），重新生成计划后再点一次“测试并获取航路”。

> 注意：SimBrief 的 `json=v2` 响应里航路点是**扁平数组**（`navlog: [ … ]`），旧格式才是 `navlog.fix`。两种形态本项目都支持（0.2 版曾经只认后者，导致“勾选了 Detailed Navlog 仍显示 0 个航点”）。

### 原始数据诊断（-999 之类的疑问）

想知道 X-Plane 每个数据行的 8 个槽位到底装了什么，可以采样一段原始 UDP：

```powershell
.\XPlaneEfbBridge.exe --dump-udp "$env:LOCALAPPDATA\XPlaneEfbBridge\bridge-config.json" 20
```

它按 `UdpPorts` 监听 20 秒（进入飞行后才有数据），逐行打印每个槽位的最小值、最大值、最后值和有效样本数，恒为 -999 的槽位会直接标注为“X-Plane 表示无数据”，并把同样的报告写到配置目录下的 `udp-dump.txt`。其它命令行开关还有 `--headless <配置>`（不开界面跑服务）、`--config-selftest <目录>`（75+ 项自检）、`--repair-config <配置>`、`--settings-preview <png> [标签页|folder]`。

采样前请先从托盘退出正在运行的桥接器：UDP 端口是共享的，两个进程同时监听同一个端口时只有一个能收到包。

## 验收步骤

1. 双击运行 `XPlaneEfbBridge.exe`，确认托盘出现图标。
2. 右击托盘选择“在本机打开 EFB”，确认电脑浏览器能显示地图。
3. iPad 与电脑连接同一 Wi-Fi，打开托盘显示的 `http://电脑IP:8080`。
4. 网页顶部初始显示“等待 UDP”，抽屉中 WebSocket 应显示“已连接”。
5. 在 X-Plane 启用 DATA 行 3、4、17、20，并发送到电脑 IP和桥接 UDP 端口。
6. 托盘应显示 `XP12 发送端IP · UDP 端口 · 设备数`。
7. 网页在数秒内显示实时状态、飞机位置、GS、ALT、HDG 和 V/S。
8. 在 X-Plane 改变航向/高度，确认图标、数值和轨迹同步；点击“航向向上”，确认飞机朝上、地图随航向平滑旋转，再次点击应恢复北向上。
9. 保持“航向向上”飞行 2–3 分钟：底图应持续可见、飞机图标稳定在屏幕中心附近（旧版本会在此处出现底图空白与图标乱飞）。
10. 在抽屉中点击“获取/刷新航路”，确认出现航路虚线、航点圆点和起降/备降机场标签；随后重启 exe 并重新打开网页，应直接显示缓存航路而不再请求 SimBrief。
11. 打开 `http://电脑IP:8080/api/status`，确认 `packets`、`parsed` 增长且 `hasPosition` 为 true。
12. 暂时关闭 Wi-Fi再恢复，确认 WebSocket 自动重连。
13. 设置… → 地图 → “选择文件夹…”选出 X-Plane 12 目录后保存，回到 iPad 打开 🛬 并放大到 ≥15 级：应看到跑道/滑行道/标线/机位（首次会先提示“正在建立机场索引”）。

## 常见问题

**iPad 打不开网页**：确认 exe 仍在托盘；两台设备同一 Wi-Fi；使用电脑 IP而非 localhost；检查 TCP 8080 专用网络防火墙和路由器设备隔离。

**网页能打开但一直等待 UDP**：检查 X-Plane 目标 IP、端口和四个 Network via UDP 复选框；查看 `/api/status` 的 `packets` 是否增长。

**UDP 49000 被占用**：同机运行时较常见。把 exe 配置和 X-Plane 目标同时改成 49003。

**`packets` 增长但 `parsed` 为 0**：收到的不是标准 `DATA` 协议或只有不支持的行。确认 X-Plane 使用 Data Output，而不是其他插件自定义格式。

**只有部分数值**：对应 Data Output 行没有启用。桥接器会保留其他有效字段，这是预期容错行为。

**显示 UDP 数据超时**：三秒内没有新数据。检查 X-Plane是否暂停输出、电脑睡眠、Wi-Fi 丢包或防火墙策略。

**V/S 一直显示 -999**：X-Plane 用 -999 表示“这一格没有数据”，它可能整段飞行都留在 Data Output 行 4 的 VVI 列里。新版把 -999 判定为无效值，改用高度（行 20）推算垂直速度（最小二乘斜率 + 指数平滑，高度跳变会重置），平飞时归零；能读到真实 VVI 时优先用模拟器的值。想确认这份数据到底长什么样，见下面“原始数据诊断”。

**切换 X-Plane 目录后地面图层仍然没有数据**：旧版只在启动时读一次目录。新版每次查询都会重新解析配置，保存后立即在后台重建索引；若仍无数据，看 `http://电脑IP:8080/api/ground/status`，里面会说明是“未配置”“没找到 apt.dat”“没解析到机场”还是“附近 8 海里内没有机场”。

**点“选择文件夹…”时 exe 直接退出**：旧版用的是 Windows 系统文件夹对话框，它要加载系统里安装的所有 Shell 扩展（网盘、下载器、文件管理器等），其中一个有缺陷就会连带进程一起崩溃。新版改成程序内置的选择器，不再经过 Shell，也不会因此崩溃；同时可以直接把路径粘贴进输入框。

**OSM 地图空白但飞机数值正常**：局域网遥测正常，但 iPad 无法访问 OSM 瓦片互联网服务。低流量个人使用仍需遵守 OSM 瓦片政策。

**开启“航向向上”后底图空白、飞机图标乱飞**：这是旧版本旋转扩展的缺陷——旋转地图 pane 会让 Leaflet 的地图 pane 偏移无上限累积，最终瓦片停止绘制、图标飞出屏幕。新版改为对整个地图容器做 CSS 旋转，指针坐标再换算回地图坐标系，不再使用该扩展。若仍复现，请确认 iPad 加载的是更新后的网页（`index.html` 与 `app.js?v=` 版本一致），而不是浏览器缓存中的旧版本：先刷新页面，必要时清除该站点数据后重新打开。

**航向向上时瓦片请求变多**：为了旋转后四角不露白，容器会放大到屏幕对角线大小，因此同时可见的区域更大、瓦片数量约为北向上时的两倍；切回北向上会自动恢复到 1 倍。

**点击“获取/刷新航路”没有反应或提示未配置**：在配置文件中填写 `SimbriefUser`（Pilot ID 或 Navigraph 用户名）后，从托盘选择“重新加载配置”。

**设置窗口在哪里**：右击 Windows 任务栏通知区域（右下角）的托盘图标 → “设置…”。双击托盘图标打开的是 iPad 网页，不是设置。

**双击 exe 提示“已经在运行”**：这是故意的。同一个 exe 只允许一个实例，否则两个进程会抢同一个端口、同时写同一个配置。请到托盘图标里打开设置。

**保存后端口没变**：网页端口和 UDP 端口必须重启服务才生效。保存时如果选了“稍后”，托盘状态会显示“端口改动待重启服务生效”，随时可以在托盘菜单点“重新加载配置（重启服务）”。

**保存时提示端口被占用**：说明新端口已被其它程序占用（也可能是另一个桥接器实例、或 X-Plane 自己占用了该 UDP 端口）。换一个端口，或者先关掉占用它的程序。只改没被占用的端口时不会触发这个提示。

**保存时提示“配置文件在设置窗口打开期间被其它程序修改过”**：你（或其它工具）在窗口打开时改过这个 JSON。选择“是”会用界面上的设置覆盖（覆盖前仍然会备份），选择“否”会放弃本次修改并重新载入磁盘内容。

**设置窗口里的字段旁边出现红字**：那是校验提示，例如端口重复、URL 缺少 `{z}/{x}/{y}`、代理地址写法不对。修正后再次保存即可；有红字时**不会**写出任何文件。

**想找回之前的配置**：点“高级”→“打开配置文件夹”，同目录里能看到 `bridge-config.json.<时间戳>.bak`（每次保存前的自动备份）和 `bridge-config.json.invalid-<时间戳>.bak`（旧版修复损坏文件时的备份）。程序不会自动删除这些备份。

**提示“请求过于频繁”**：这是防止误触连续调用 SimBrief 的保护，等待提示的秒数后再点。SimBrief 明确禁止轮询，本项目不会自动重试或后台刷新。

**航路获取失败（未知用户 / 超时）**：核对 Pilot ID 是否为 1–7 位数字，或用户名是否与 SimBrief 账号一致；确认运行 exe 的电脑能访问 `www.simbrief.com`。网络受限时可用 `SimbriefApiUrl` 指向你自己的代理端点。

**航路已获取但地图上没有线**：确认抽屉里的“SimBrief 航路”已勾选，并把地图缩小到能看到整个航段；航点坐标缺失的计划只会显示能确定位置的部分。

**JSON 提示 `invalid after a single JSON value`**：文件中存在第二个 JSON 对象或根对象后的多余文本。使用新版 exe 会自动备份并修复；修复后的文件应只包含一对最外层 `{}`。

**托盘选择“退出”后图标变灰、进程仍存在**：新版已将同步阻塞式关闭改为异步关闭，并会主动中止 WebSocket、释放 UDP、在 4 秒内停止 Kestrel 后结束消息循环。请确认正在运行的是 `windows-bridge\dist` 中的最新版 exe。

**出现多个访问 IP**：虚拟机/VPN可能创建额外网卡。新版 exe 会优先显示具有默认网关的 Wi-Fi/以太网地址；仍应选择和 iPad 同一网段的地址，例如手机热点网关是 `192.168.43.1` 时选择电脑的 `192.168.43.x`，不要选择 VMware/Hyper-V 虚拟网卡地址。

**exe 被 SmartScreen 提示**：自构建或未签名 exe 的常见现象。核对来源；正式分发请进行代码签名，不应指导用户绕过系统安全警告。

**配置后没有变化**：保存 JSON 后从托盘选择“重新加载配置”；检查 JSON 逗号和引号格式。

## 安全边界

服务监听 `0.0.0.0` 是为了让 iPad 访问。它没有登录鉴权，因此只适合可信家庭/训练局域网。不要配置路由器端口转发，不要在公网网络配置文件上放行规则；不可信局域网中应设置 `SourceIp` 并用 Windows 防火墙限制来源网段。

与本项目相关的其他边界：

- SimBrief 的 Pilot ID / 用户名只保存在运行 exe 的电脑的本地配置里，不会下发给网页或其他设备；iPad 只从桥接器读取已经解析好的航路，不直接访问 SimBrief。
- SimBrief 返回的航点标识、航路字符串在渲染前会做 HTML 转义（只作为文字显示，不会被当成页面内容执行）。
- 桥接器不向任何服务器上传遥测；离开本机的对外请求只有你主动触发的 SimBrief 航路拉取（以及 iPad 自己加载 OSM 瓦片）。
- 自定义底图 URL 与署名字段会原样下发到 iPad 浏览器并作为 HTML 注入署名栏，因此只能填写你自己信任、且拥有展示授权的地址，不要放长期密钥。
- 设置界面只存在于桌面端：**没有**任何“通过网络修改配置”的接口，因此局域网里的 iPad 或其它设备改不了配置。配置与航路缓存都写在 `%LOCALAPPDATA%\XPlaneEfbBridge\`（当前用户目录，不需要管理员权限），航路缓存里只保存账号的哈希而不是 Pilot ID。
- 代理设置不含账号密码：手动代理地址里带 `用户名:密码` 会被设置界面拒绝，需要认证请用“系统代理”，让 Windows 保管凭据。
