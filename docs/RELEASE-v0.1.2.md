# v0.1.2 更新说明

发布日期：2026-09-12 · 适用平台：Windows x64（单文件 exe，目标电脑无需安装 .NET）
下载文件：`XPlaneEfbBridge-v0.1.2-win-x64.exe`

本次处理四件事：SimBrief 拉取超时、航迹保留太短、飞机图标、航路点名称的显示门槛。

## 1. 修复 exe 拉取 SimBrief 超时

**原因**：SimBrief 请求走“高级”页里的代理设置，默认值是**系统代理**；但旧版在第一次请求时把解析出来的系统代理缓存到进程结束。Windows 代理是运行期才会打开的（Clash 等），因此浏览器能访问 SimBrief、exe 却一直超时；配置没有变化时缓存也不会失效。

**修复**：

- 系统代理改为**每 45 秒重新解析**一次（含 PAC），代理被打开/关闭/换端口后自动跟上；Windows 没有配置代理时回退读取 `HTTPS_PROXY`/`HTTP_PROXY` 环境变量。
- 每个请求独立超时：SimBrief 35 秒、天气瓦片 20 秒；失败自动重试一次（350 ms 退避）。调用方取消（iPad 关掉页面）不重试、不吞异常。
- 启用响应压缩（`AutomaticDecompression`），并把 Windows 身份交给代理（`DefaultProxyCredentials`），兼容需要认证的公司代理。
- 错误信息给出**原因 + 实际出口**，例如 `请求超时｜当前走：系统代理 127.0.0.1:7897`、`连接被拒绝（对端或代理端口没有监听）｜当前走：系统代理 127.0.0.1:9`、`域名解析失败（DNS）｜当前走：不使用代理（直连）`。设置窗口的“测试并获取航路”也会显示当前使用的链路。
- 顺带修掉一处配置隔离问题：SimBrief 历史与机场索引缓存原来固定写在默认配置目录，`--headless <其他配置>` 会串用；现在缓存跟着**当前生效的配置文件**走。

## 2. 航迹保留

旧版硬编码只保留 **2 000 个点**（巡航时约 4 分钟）。现在侧栏“显示”里可选：

| 选项 | 行为 |
| --- | --- |
| 永久保留（默认） | 直到手动清除；超过顶点预算时对较早部分抽稀，最近 4 000 点保持全分辨率 |
| 最近 6 小时 / 1 小时 | 按时间淘汰，另设顶点安全上限 |
| 最近 50 000 / 10 000 / 2 000 个点 | “保留最后 N 个点”的字面语义，超出即从前端截断 |

性能做法：航迹移到独立 canvas 图层（SVG 画几万顶点会卡），点数超过 12 000 自动省略外发光描边，绘制节流到 2.5 Hz，永久保留模式下同时写入浏览器本地存储，刷新页面不丢。抽屉里常驻显示“已记录 N 个点 · 跨度 X 小时 YY 分”。

保留策略是纯函数模块（`public/track-retention.js`），带 6 项 Node 单测。

## 3. 飞机图标

换成三种内联 SVG 主题，侧栏即可切换并记住选择：

- **现代客机**（默认）：白机身 + 青色机头 + 深色描边 + 阴影，俯视客机轮廓；
- **简约箭头**：琥珀色飞镖；
- **经典三角**：青色三角 + 中心点。

都是矢量，任何缩放级别都清晰、不额外发请求；机头朝上绘制，旋转沿用 CSS `rotate(航向)`，旋转中心就是图标中心。

## 4. 航路点名称显示门槛

从缩放 7 级降到 **5 级**（约大陆尺度就能看到名字），同时把碰撞处理换成按文字实际宽度计算的矩形检测：优先显示 VOR/NDB，其次按距屏幕中心由近到远，最多 90 个，永不压住飞机图标；6 级及以下字号 12px、7 级起 14px。实测在 6 级时一条洲际航路能稳定显示约 11 个不重叠的名称（改前该缩放下一个都不显示）。

## 升级方式

替换 exe 即可，配置与历史计划都在 `%LOCALAPPDATA%\XPlaneEfbBridge\`。iPad 端因为前端资源版本升到 `v25`，刷新一次页面即可。

自检：`XPlaneEfbBridge.exe --config-selftest <空目录>` 共 91 项；Node 测试 26 项。
