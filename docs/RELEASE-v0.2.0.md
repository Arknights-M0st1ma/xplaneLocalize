# v0.2.0 更新说明

发布日期：2026-09-13 · 适用平台：Windows x64（单文件 exe，目标电脑无需安装 .NET）

本次是功能级更新：**桥接器现在可以跟随 Train Sim World 6**，与原有的 X-Plane 12 数据源二选一。

---

## 1. 新增：Train Sim World 6 数据源

TSW6（PC 版）内置一个官方 HTTP API，默认监听 `http://127.0.0.1:31270`，用游戏自己生成的密钥
`CommAPIKey.txt` 做请求头认证。桥接器现在可以直接读它，把列车的位置、速度、限速和信号推给同一张地图。

### 为什么必须由 exe 代读，而不是网页直连

| 方案 | 结论 |
| --- | --- |
| 网页 JS 直接请求 `127.0.0.1:31270` | **不可行**：iPad 根本连不到游戏机的回环地址；而且要把密钥交给浏览器 |
| 桥接器代读后走现有 `/ws` 推送 | **采用**：与现有架构完全同构，密钥不出本机，同源无 CORS |

### 启用方式

1. Steam → TSW6 → 属性 → 启动选项，加入 `-HTTPAPI`，然后启动一次游戏。
2. 游戏会生成密钥文件：`文档\My Games\TrainSimWorld6\Saved\Config\CommAPIKey.txt`
   （OneDrive 重定向文档目录的情况也会自动查找；主机版没有这个 API）。
3. 电脑端托盘 → **设置…** → **数据源** 页 → 选“Train Sim World 6” → 点“测试连接”确认能读到位置 → 保存。
4. 保存时会询问是否立即重启服务；重启后 iPad 刷新一次页面即可。

### 数据源是二选一，不是并存

两者都会写同一份位置/协议字段，同时接收只会让地图上的图标来回跳。切换数据源需要重启服务，
重启时会清空上一数据源留下的所有字段（下面第 3 节说明原因）。

### 列车模式下界面会怎么变

| 位置 | 变化 |
| --- | --- |
| 位置图标 | 自动换成列车图标，并锁定（不再显示飞机图标选择器） |
| `GS` | 改成 **km/h**（游戏 API 的速度单位是 m/s） |
| `ALT` | 改成 **限速**（当前区间限速，km/h） |
| `V/S` | 改成 **距下一限速**（米 / 公里） |
| `HDG` | **移除**：游戏 API 没有航向字段，用相邻点外推得到的方向在停车、调车、折返时会误导 |
| 侧栏“显示” | **隐藏**“飞机图标”选择器 |
| SimBrief 航路 | **整块隐藏**（飞行计划对铁路无意义，也不再请求） |
| 🛬 机场地面图层 | **隐藏**（那是机场滑行道数据，不是铁路，也不再请求 `/api/ground/*`） |
| 航司徽章 | **隐藏** |
| 天气图层 | **保留**（真天气对驾驶同样有意义） |
| 新增列车卡片 | 车次 / 速度 / 当前限速 / 下一限速 / 距下一限速 / 前方信号 / 距信号 / 坡度 / 更新时间 |
| 抽屉“数据链路” | 第三行改成 **TSW 端点**，显示哪个端点正在提供数据 |

### 轮询频率

游戏 API 只有请求/响应、没有推送，所以由桥接器轮询，默认 **4 Hz**（可设 1–10 Hz）。
每帧都会变成一条发给每个 iPad 的 WebSocket 消息，所以不建议调到 10 Hz。

### 端点名不是硬编码猜的

TSW6 的端点名（`DriverAid.PlayerInfo` 等）来自第三方逆向资料——官方 PDF 需要论坛登录才能下载，
本项目**没有**把它复制进仓库。因此实现方式是：

- 启动时按候选名单探测位置端点（`DriverAid.PlayerInfo` → `DriverAid.Data` → `CurrentDrivableActor.LatLon` …）；
- 只接受**真的带经纬度**的响应，端点存在但字段不对不算通过；
- 可选端点（速度、限速）读不到时**安静降级**，界面显示 `—`，抽屉里说明原因，不会反复重试；
- 位置端点失效后会冷却 30 秒再重新探测一次，这样游戏更新改了路由名也不会直接变哑巴；
- `--tsw-probe`（见下）会打印游戏**实际暴露**的端点清单。

## 2. 新增：`--tsw-probe` 诊断开关

```powershell
XPlaneEfbBridge.exe --tsw-probe "$env:TEMP\tsw-probe.txt" "$env:LOCALAPPDATA\XPlaneEfbBridge\bridge-config.json"
```

一次运行即可得到：可达性、密钥文件位置、`/list` 是否成功、关键节点的端点清单、候选端点的原始响应
以及桥接器从每个响应里取到了哪些字段，最后给出“可用的位置端点”结论。用于在没有开发者介入的情况下
核对真实游戏版本。

报告里**不含密钥**；可能含玩家名（`playerProfileName`），介意可自行删掉那两行。

## 3. 修复：切换数据源时的陈旧字段污染

`Publish` 的快照合并是**只增不减**的。旧版一旦先跑过 X-Plane，快照里就有 `altitudeMslFt`，
切到列车源后列车不写高度，这个旧值会一直留着；而按高度推算垂直速度的估计器每次 `Publish` 都会读它，
于是**持续把上一段飞行的假高度喂进去，并写出一个完全虚构的升降率**。

现在 `LocalWebServer.ClearSnapshot()` 会在启动、数据源切换时清空快照和估计器历史；
列车帧也不参与垂直速度推算。自检里加了一条回归断言，先证明“旧字段确实会残留”，再证明清空后不再出现。

## 4. 修复：列车模式不再谎报 UDP

飞行模式下“等待 UDP”“UDP 数据超时”这类文案在列车模式下是错的。状态文案现在按数据源切换
（“等待 TSW 数据”“TSW 数据超时”），来源诊断行显示实际端点。

## 5. 其他

- **修复 `Same()` 漏比较字段**：`XplanePath`、`GroundMinZoom`、`AirlineLogoUrlTemplate`、天气 Key、
  天气代理三项原先没有参与“有没有改动”的判断，只改这些项后直接关窗口会被当成“未修改”而静默丢弃。
- `ContainsSecret()` 现在也识别 `apikey=`。
- 免责声明扩展为“仅用于模拟飞行/模拟驾驶娱乐，不得用于真实导航或真实铁路调度”。
- 设置窗口新增第 2 个页签“数据源”，页签顺序变为：连接 / 数据源 / 地图 / SimBrief / 天气 / 高级。
  `--settings-preview` 的页签序号随之变化（0–5）。

## 测试与验证

| 项 | 结果 |
| --- | --- |
| Node 测试 | **55 项全通过**（原 26 项 + TSW 假 API 14 项 + 协议判定 8 项 + 列车演示 6 项 + 1 个文件级条目） |
| C# 自检（离线） | `--config-selftest` **120 项全通过**（原 91 项 + TSW 29 项） |
| C# 自检（对假 API） | 设 `EFB_TSW_FAKE_BASE` 后 **131 项全通过**（多出 11 项真实 HTTP 端到端检查） |
| `--tsw-probe` 实测 | 对假 API 运行：读到 5 个根节点、各节点端点清单、`/info` 的 `Meta`，并正确判定位置端点 |
| 编译 | `dotnet build` 0 警告 0 错误 |

> 自检过程中确实抓到过两个真实缺陷，都已修复并加了回归断言：① 字段归一化只查顶层，
> 而游戏把坐标放在 `geoLocation` 里，导致**整帧被丢弃**；② `/list` 与 `/info` 把数据放在 JSON 根上
> （不是 `Values`），只读 `Values` 会让**端点清单和游戏信息全空**。后者正是 `--tsw-probe` 的设计目的。

**开发机没有装游戏也能验证的通道**（这是本次特意设计的，因为开发机与游戏机不是同一台）：

```powershell
npm test                    # 假 API + 协议判定 + 列车演示的单元测试
npm run demo:tsw            # 用列车形状的演示数据在浏览器里看列车模式（默认 8081 端口）
node test/tsw-fake-api.js   # 在 31270 起一个假 TSW API，可配 XPlaneEfbBridge.exe --tsw-probe 对打
```

`test/tsw-fake-api.js` 支持 `ok` / `no-info` / `bad-key` / `error-envelope` / `slow` / `minimal` / `offline`
七种场景，其中 `error-envelope` 专门覆盖“HTTP 200 但 `Result:"Error"`”这个最容易写错的失败形态。

## 升级方式

替换 exe 即可，配置与历史计划都在 `%LOCALAPPDATA%\XPlaneEfbBridge\`。
旧配置会原样保留并得到 4 个新键（`TelemetrySource` 默认为 `xp`，行为与旧版一致）。
iPad 端前端资源版本升到 `v26`，刷新一次页面即可。

## 仍需在游戏机上确认的事（本项目无法代为验证）

以下各项来自第三方逆向资料，安装游戏后可一次跑 `--tsw-probe` 核对：
坐标贴合实际线路的程度、限速/信号字段名、是否有航向字段、订阅（`/subscription`）是否可用、
端口能否修改、API 是否只监听回环。详见 `docs/TSW6-TELEMETRY.md` 第 9.2 节。
