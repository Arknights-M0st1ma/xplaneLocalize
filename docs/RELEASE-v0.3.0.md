# v0.3.0 更新说明

发布日期：2026-09-23 · 适用平台：Windows x64（单文件 exe，目标电脑无需安装 .NET）

本次三件事：**修掉「到目的地的时间」算错**、**把航迹改由电脑端记录**，以及**界面换成 iPad 优先的「航司资料包」风格**。

## 1. 修复：剩余距离 / 剩余时间 / 预计到达全部偏小 57 倍

### 现象

飞行卡片上的「剩余距离」几乎不随飞机移动变化，永远显示很小的值（测试时是 `10 NM`），
「剩余时间」永远是 `0h01m`，「预计到达」永远是一分钟后——看起来就像目的地被钉在出发地旁边。

### 原因

`public/app.js` 里的 `nmBetween()` 把经纬度差先换成**弧度**，再乘上「每度 60 海里」这个
**按度数定义**的常量：

```js
const dLat = (b[0] - a[0]) * RAD;          // 弧度
const dLon = (b[1] - a[1]) * RAD * Math.cos(...);
return Math.sqrt(dLat * dLat + dLon * dLon) * NM_PER_DEGREE;   // ×60，按度数的常量
```

弧度与度相差 57.2958 倍，所以**每一段距离都小了 57.2958 倍**。

这一条同时解释了为什么进度百分比看起来是对的：`剩余距离` 与 `总距离` 用的是同一个函数，
分子分母同时缩小，比值不变（39% 就是对的）。错的只有绝对距离，以及由距离推算的**时间与 ETA**。

同一个函数还被机场地面图层的「飞机是否还在同一机场」判断使用，那次比较的阈值 `1.5`
实际等于 86 海里，所以地面图层几乎从不重新查找最近的机场。

### 修复

- 新增 `public/geo.js`：`nmBetween()` 用标准大圆（Haversine）公式，`metresBetween()` 供米制比较使用。
- `app.js` 改为从该模块导入，删掉本地那份错误实现。
- 地面图层的阈值改成具名常量 `GROUND_REANCHOR_NM = 4`（查询半径 8 海里的一半），语义终于和注释一致。
- 新增 `test/geo.test.js` 6 项回归：1 度纬度 = 60 海里、1 度经度按纬度余弦收缩、
  上海浦东 → 东京成田 ≈ 970 海里、对称性与零距离、米/海里换算，以及「700 海里的航段不能报成 12 海里」。

修复后同一位置（途中、距成田约 600 海里）实测：`剩余距离 598 NM`、`剩余时间 1h15m`、
`预计到达 16:42Z`、进度 `39%`，四者互相自洽。

## 2. 变更：航迹改由电脑端记录，浏览器只读取

### 之前为什么不行

航迹是浏览器自己累积的：每收到一帧遥测就往数组里塞一个点。可 iPadOS 会把 Safari 挂起
（切到别的 App、锁屏、来电、切到后台），挂起期间**一帧都收不到**，回来之后中间那段就永久缺失了。
这不是采样策略能解决的问题——记录者本身会睡着。

### 现在的分工

```
模拟器 → 桥接器（PC，常驻）
            ├─ 记录航迹：移动 ≥ 0.1 NM 或每 5 秒一个点，上限 40 000 点
            ├─ 落盘：%LOCALAPPDATA%\XPlaneEfbBridge\track.json（每 20 秒 / 退出时）
            └─ GET /api/track?since=<毫秒>  →  全量或增量
iPad → 只做两件事：取回来、画出来（Leaflet，保留原三层描边）
```

| 细节 | 行为 |
| --- | --- |
| 采样 | 移动 ≥ 0.1 NM 记录一点（450 节时约 0.8 秒一个），最快 1.4 Hz；原地不动每 5 秒补一个心跳点，停车/等待的形状不丢 |
| 增量读取 | 页面带上自己最新的时间戳，只取之后的部分；一次补上挂起期间错过的整段 |
| 断档保护 | 若页面手上的时间戳早于服务端保留范围（例如刚被清空），响应里 `replaced=true`，页面整体替换而不是接在错误的后面 |
| 容量 | 服务端最多 40 000 点（约 6 小时巡航）；「航迹保留」选择器仍然只决定**本页画多少**，不决定电脑端记多少 |
| 清轨迹 | `DELETE /api/track`，清的是电脑端那份，然后页面重画 |
| 兼容 | 旧版 exe 没有该接口时，抽屉里显示「（电脑端未响应）」，不会静默画一条空轨迹 |

### 涉及文件

- `src/track.js`：开发用的记录器（采样、增量读取、原子落盘）；`test/track-store.test.js` 11 项单测。
- `windows-bridge/TrackStore.cs`：exe 内同样的记录器；`--config-selftest` 新增 11 项断言。
- `src/server.js` / `windows-bridge/Program.cs`：遥测发布时顺带记录，新增 `GET/DELETE /api/track`，退出与数据源切换时落盘。
- `public/app.js`：删除浏览器端的累积与 `localStorage` 持久化，改为加载时全量拉取、每 2 秒增量拉取、
  页面重新可见 / WebSocket 重连 / 网络恢复时立即补拉。

## 3. 新界面：iPad 优先的「航司资料包」

从三版方案里选定并落地了 **B · 航司资料包**：白底航图 + 数据卡片 + 航空蓝主色 + 表格化数字。

| 位置 | 变化 |
| --- | --- |
| 顶栏 | 左侧蓝色 `EFB` 标识；有飞行计划时显示呼号（如 `ZZZ/1234`）与 `ZSPD → RJAA · 机型`，无计划时回退为产品名 |
| 仪表带 | 白底卡片，地速用主色，其余用深色；数字统一等宽（`tabular-nums`），跳动时不再抖动 |
| 飞行卡片 | 白底卡片、蓝色进度条；**预计到达**旁边的准点/延误改成独立徽章（准点 / 晚 x / 早 x），不再挤成三行 |
| 抽屉 | 白底面板 + 蓝色小标题 + **iOS 风格开关**；滑块、下拉框、按钮都按 iPad 触摸尺寸放大（≥ 44px） |
| 底图元素 | 航迹、航路、航点、机场、地面图层、飞机图标的配色改由调色板提供，随主题切换 |
| 夜间模式 | 现在切换**整套界面**的明暗（以前只反转底图），并且不再使用 `backdrop-filter` 毛玻璃层 |

布局规则：宽度 ≥ 900px（横屏 iPad）时抽屉常驻在右侧、地图缩小而不被遮挡；
更窄（竖屏 iPad / 手机）时抽屉变成带遮罩的覆盖层。所有尺寸走安全区（`env(safe-area-inset-*)`）。

夜间模式下无需重新加载，配色即时生效；地图矢量图层会在切换时重新着色。

## 升级方式

替换 exe 即可；配置、历史计划与航迹都在 `%LOCALAPPDATA%\XPlaneEfbBridge\`。
iPad 端前端资源版本升到 `v27`，刷新一次页面即可（若启用了 PWA 缓存，请先关闭再打开一次）。

> 本版**必须**同时更新 exe：网页已经不再自己记录航迹，旧 exe 没有 `/api/track`，航迹会显示为空。

## 仍需在游戏机上确认的事

与 v0.2.0 相同：TSW6 端点字段名、坐标贴合度、限速/信号字段等仍需用 `--tsw-probe` 在装有游戏的机器上核对。
