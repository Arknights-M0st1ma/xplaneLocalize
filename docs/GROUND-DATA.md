# 不依赖 Navigraph 获取机场地面数据（滑行道/标线/机位）的可行性研究

核对时间：2026-09-11。调研结论已完成，**首选方案（本机 apt.dat）已实现**：见 `windows-bridge/AptDat.cs` 与设置里的“X-Plane 12 安装目录 / 地面图层最小缩放”，前端为地图左侧的 🛬 开关（缩放阈值以上才渲染）。本文保留完整的来源评估与限制说明。

结论先讲：**可行，而且最佳数据源就在用户自己的电脑上——X-Plane 自带的 `apt.dat`**。它能提供滑行道铺面、地面标线、滑行道标牌（编号）和机位/启动位；这些数据与模拟器里看到的完全一致，且无需任何授权或联网。OSM 可以作为“模拟器里没有的机场”的补充；其余来源都不适合这个需求。

## 二、为什么推荐 apt.dat

1. **正好覆盖你列出的前三项**：
   - 地面滑行标线 → `120` 线性特征（painted line / light string）；
   - 滑行道编号 → `20` 滑行道标牌，牌面文本就是编号（例如 `{@L}A1{@R}31R-13L`）；
   - 机位号 → `1300` 启动位（名称字段，例如 `A8`）与 `1301` 元数据（尺寸代码、航司代码）；
   - 另外还白送：滑行道/机坪铺面几何（`110`+节点）、ATC 滑行路线（`1200–1206`）、跑道与机场边界。
2. **与模拟器所见一致**：你在 X-Plane 里看到的滑行道，就是这份数据画出来的；不会出现“图上有、模拟器里没有”的错位。
3. **零授权、零联网、零成本**：只读用户自己电脑上的文件，和之前读 `earth_fix.dat` 航点数据的边界一样——**只读、不分发**。
4. **性能可控**：默认 `apt.dat` 很大，但只需要按当前飞机所在机场定位记录区间（扫描 `1`/`1000` 机场头行）再解析该区间；结果缓存，机场切换才重新解析。可以只在“地面图层”开关打开时才做。

**限制（必须如实告知）**
- 只有**你安装过的机场**有数据；如果第三方地景做得烂或没做，地面就会很粗糙。
- 第三方地景可能不规范（缺标牌、机位命名随意），解析器要能容错。
- 数据只反映模拟器，**不能用于真实飞行**（与本项目一贯声明一致）。

## 三、建议

1. **值得接入（首选）**：本机 `apt.dat` 地面图层。
   - 只读用户本机文件、**不打包、不分发**；UI 上提供“地面图层”开关（默认关闭），显示：滑行道/机坪面、标线、滑行道标牌文字、机位点与编号；可选显示 ATC 滑行路线。
   - 仅解析当前机场，缓存结果；机场切换后再解析下一个；解析放在后台线程，避免卡地图。
   - 需要你在设置里指定 X-Plane 安装目录（你已确认先不加自动搜索）。
2. **可选补充**：OSM（Overpass 在线查询）用于模拟器里缺失的机场。默认关闭、需联网、显示 ODbL 署名，且**不把数据落地分发**。
3. **不适合**：MSFS BGL 逆向（法律/技术风险高）、OpenAIP（没有地面滑行数据）、FAA（仅美国且以图为主，除非你只飞美国）。
4. **不做**：任何需要把第三方数据打包进 exe 再分发的做法（OurAirports 除外，它没有地面数据）。

## 四、如果将来实施，验收标准（预留）

- 打开地面图层后，当前机场的滑行道铺面/标线与模拟器里位置一致（同一机场截图比对）；
- 滑行道标牌文字与机位号正确显示，且不影响航迹/航路/天气图层性能（开关关闭时零开销）；
- 未安装 X-Plane 或路径未配置时给出明确提示，不影响其它功能；
- 数据来源与限制在 README 中说明，界面保留“仅用于飞行模拟”的声明。
